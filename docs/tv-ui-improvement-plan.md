# TV 首页 UI 与遥控器交互改进计划

## 目标

让 TV 入口在三米观看距离下更清晰、更易操作，并保留现有直播预览与频道列表能力。

本计划不处理节目源兼容性、解码或直播预览链路的问题。

## 当前基线

- 默认进入 Browse 页面时，分类侧栏展开，频道内容不是首个焦点目标。
- 灰白背景、青色侧栏和橙色选中卡片同时占据主视觉，页面层级分散。
- 频道卡片信息区较高，频道名常被截断，重复的“直播频道”没有提供额外信息。
- 收藏目前依赖 Menu 键，和页面提示中的“长按”不一致；收藏更新会重建列表，存在焦点跳动风险。
- 播放页只响应 Channel/Page 按键切台，未覆盖常见遥控器的上下键习惯。
- 设置页沿用手机表单样式，不适合方向键浏览和远距离阅读。

## 设计原则

1. 焦点优先：任何时刻都能一眼确认当前将要执行操作的频道或按钮。
2. 内容优先：频道画面是首页主视觉，导航和文字不抢占内容空间。
3. 遥控器优先：确认、返回、上下左右和长按确认是主要交互路径。
4. 稳定优先：收藏、刷新和预览状态变化不应让焦点或滚动位置跳动。
5. 分辨率自适应：在 720p、1080p 和当前横屏测试设备上均保持安全边距与可读性。

## 实施批次

### 1. TV 首页视觉基础

范围：颜色、背景、频道卡片、焦点样式、首页留白和沉浸式显示。

- 建立深色背景与统一的品牌色资源；将橙色限制为焦点和强调状态。
- 调整频道卡片的图文比例，减少重复副标题，突出频道名与预览画面。
- 使用整卡缩放、描边和阴影表达焦点；焦点动画在 120 至 160ms 内完成。
- 根据可用宽度计算卡片尺寸和间距，目标是在 1080p 下稳定显示约 5 至 6 张卡片。
- 让 TV 首页隐藏系统栏，保留足够的电视安全边距。

验收：连续横向移动 10 次时焦点不丢失、无明显掉帧；焦点切换的视觉反馈在 100ms 内开始；频道名称和静态/直播预览都保持完整可见。

### 2. 首页焦点与遥控器交互

范围：启动焦点、侧栏、收藏、状态更新和位置恢复。

- 默认折叠分类侧栏，将焦点落到最近观看、收藏或首个可播放频道。
- 记住返回首页前的分组、频道和横向位置。
- 长按确认键切换收藏，保留 Menu 键作为兼容入口；在原卡片上即时更新收藏状态。
- 通过差量更新频道和收藏行，避免重建整个列表。
- 将“设置”移动到侧栏底部或独立入口，移除频道列表末尾的设置卡片。

验收：收藏后焦点和滚动位置不变；按左键或返回键可预测地打开侧栏；再次进入首页回到上次浏览位置。

### 3. 直播播放页交互

范围：遥控器按键映射、频道信息层和错误反馈。

- 上下键、Channel 键和 Page 键均可切换频道。
- 确认键显示或隐藏频道信息层；首次播放和切台后短暂显示频道名、分组和操作提示。
- 直播页不显示不适用的通用进度控制器。
- 错误状态提供“下一频道”为主操作，“重试”和“返回列表”为次操作，仍可用上下键切台。

验收：常用电视遥控器不依赖特殊按键即可完成切台、查看信息和返回列表。

### 4. 搜索、设置与状态反馈

范围：搜索空状态、TV 设置页、加载和离线反馈。

- 搜索空状态展示收藏、最近观看或常用分组，降低输入成本。
- 设置改为 TV 友好的分组列表和独立编辑页面，提供明确的焦点态、检测状态和保存结果。
- 将加载、离线和缓存提示放到页面顶部轻量状态条，保留已有频道内容。

验收：无键盘输入时用户也能在搜索页继续浏览；设置的所有操作都可通过方向键和确认键完成。

### 5. 流畅度、可访问性与回归

范围：动画、性能、可读性和设备回归。

- 静态帧切换为直播画面时使用短交叉淡入，避免黑帧或跳闪。
- 限制滚动期间的非必要预览与背景更新，优先保证焦点动画流畅。
- 检查文字对比度、焦点描边、TalkBack 文案和电视安全边距。
- 在 720p、1080p 和当前测试设备完成方向键路径、播放页、搜索和设置回归。

## 提交与验证策略

每个批次独立提交。每次提交至少包含：

1. 涉及状态逻辑时的对应单元测试或状态逻辑测试。
2. `testDebugUnitTest`、`lintDebug`、Debug 与 Release 打包验证。
3. 真机截图与遥控器路径验证。
4. 对焦点位置、静态预览和收藏数据的回归检查。
