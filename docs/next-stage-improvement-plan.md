# TV 下一阶段产品与体验改进计划

基线：2026-09-23，`54fc92f`。本计划从「能否稳定找到并播放想看的频道」出发，覆盖设置、节目源、找台和预览成本。此前的视觉与遥控器改进见 [TV 首页 UI 与遥控器交互改进计划](tv-ui-improvement-plan.md)。优先实施 TV 入口；共享逻辑改动需回归手机入口。

进度：P0-1 设置入口与设置主页、P0-2 安全切换与备用节目源、P1-1 预览模式与流量预算、P1-2 最近观看已完成；下一项为 P1-3 播放中快速选台。

## 基线发现（基于 `54fc92f`）

| 发现 | 当前代码证据 | 用户影响 |
| --- | --- | --- |
| 设置入口仍是频道列表末尾的一行 | `MainFragment.renderRows` 在全部频道行后追加设置行 | 频道多时很难找到设置；此前计划中的入口调整尚未落地。 |
| 设置页只有直播源编辑、节目单检测、保存和一个预览开关 | `activity_settings.xml`、`layout-television/activity_settings.xml`、`SettingsActivity` | 缺少正在使用的源及刷新结果、预览流量策略、缓存和历史管理等可操作信息；长 URL 依赖电视输入法。 |
| 保存直播源只校验 URL 格式，随后立即替换当前源并刷新 | `SettingsActivity` 调用 `saveSourceUrl`、`invalidate`、`refresh`；`TvDataManager` 仅保存一个当前源，快照只匹配当前源 | 新源不可用时，用户要重新输入旧地址才能恢复；“测试节目源”目前只验证节目单可解析且包含频道，不代表每路直播可播放。 |
| 搜索推荐只有收藏和首个可播放分组，首页默认焦点也没有持久观看历史 | `TvSearchRecommendationPolicy`、`TvInitialFocusPolicy`、`MainFragment` | 常看的频道仍需反复找；跨应用重启无法直接回到最近观看。 |
| 播放页支持顺序切台，但没有播放中的频道目录 | `PlaybackActivity`、`ChannelPlaybackNavigator` | 跳到较远频道需要多次按键，或退出播放回列表。 |
| 焦点直播与可见卡片静态帧由两套播放器控制器分别管理，设置仅有总开关 | `TvChannelPreviewController`、`VisibleLivePreviewController`、`ChannelPreviewPreferences` | 用户无法选择预览强度；两套控制器可能同时取流，现有“最多预览一路直播”说明需要实测核对。 |

### P0-1：设置入口与设置主页

目标：让设置容易找到，且每项信息都能回答“当前是什么、能做什么、操作后发生了什么”。

- 将 TV 设置入口移到侧栏固定位置或页眉操作区，移除频道列表末尾的设置行；从设置返回时恢复原频道焦点和位置。
- 将 TV 设置主页组织为“节目源”“预览与流量”“数据与缓存”“关于”四组。数据组显示缓存频道数和时间，关于组显示版本与遥控器操作说明；不添加无效占位项。
- 节目源组显示当前源名称或域名、上次成功刷新时间、频道数、当前是在线结果还是缓存结果，并提供明确的手动刷新入口与结果反馈。
- URL 编辑保留独立焦点流程；长链接可完整查看、取消编辑不会修改当前源。为电视输入法与 720p 滚动检查焦点回退和软键盘遮挡。

验收：无需滚动到频道列表末尾即可进入设置；720p/1080p 下所有设置项可见且可达；取消编辑、返回首页不改源也不丢焦点；刷新失败时仍能浏览旧频道。

### P0-2：安全切换与备用节目源（最需要的新功能）

目标：换源失败时仍能继续看电视，而不是把唯一可用地址覆盖掉。

- 将新地址作为候选源先抓取、解析并显示分组数/频道数；检测文案明确为“节目单检测”，避免暗示每路视频都已验证。
- 候选源成功后再激活，并保存最近一个已成功使用的源作为回退入口；失败时保留当前源、频道列表及其缓存。
- 在设置中提供“恢复上一个可用源”。后续扩为可命名的多个源、手动排序和切换；自动故障切换须先定义触发条件，避免临时网络波动导致反复换源。
- 旧版单 URL 偏好设置和快照需无损迁移。

验收：无效地址、超时、空节目单均不能覆盖可用源；成功切换后频道列表与缓存归属新源；回退后恢复旧源；单测覆盖切换、失败和迁移，模拟器验证离线场景。

### P1-1：预览模式与流量预算

- TV 设置提供“关闭 / 仅焦点频道静音直播 / 焦点直播并为稳定可见的非焦点频道逐个抓静态帧”三档，逐项说明画面和流量；手机保留原布尔开关并标明仅影响手机首页。
- TV 模式单独持久化；首次读取旧布尔值时 false 映射为关闭，true 或缺失映射为完整模式。完整模式到焦点模式清除静态帧来源缓存，焦点模式保留焦点频道离开前的最后一帧；关闭模式停流并清理预览帧。
- 静态帧控制器仅保留一个取流槽，实际滚动后等视口稳定并复查绑定、焦点和可见性；焦点预览启动优先。Debug 遥测记录焦点/静态启动、首帧耗时、视口尚未稳定时的静态启动次数（预期为 0）和并发峰值，不记录流地址。
- 已为模式迁移、帧显示策略、静态调度期限和遥测计数添加纯逻辑单测。`testDebugUnitTest`、`lintDebug`、Debug 与 Release 构建通过；720p/1080p 模拟器验证三档切换、焦点恢复、最后一帧、可见行静态帧和遥控器路径，辅助功能树能读取各模式说明及选中状态。测试视频下并发峰值为 2，快速跨行操作的滚动窗口内静态启动数为 0。

验收：三种模式的画面与取流行为一致；静态帧覆盖所有可见行；快速滚动时不启动无意义的连接，频道焦点无跳动。

### P1-2：最近观看

- 仅在 TV 正式播放页实际进入播放状态后记录来源、稳定频道 ID 和时间；记录按频道更新并限制为最近 20 条。只保存视频地址指纹用于重名频道校验，不从历史数据直接播放。
- 最近记录只解析到当前节目源、当前节目单中的可播放直播频道；来源不匹配或组列表仍属于旧源时隐藏。唯一频道的地址更新使用当前节目单对象，重复频道发生地址重排时跳过有歧义的记录。
- TV 首页在首个原频道分组之后显示“最近观看”，空搜索状态按最近观看、收藏、常用分组排列；清除入口位于 TV 设置的数据与缓存卡片。
- 已添加播放门控、数量上限/去重、来源隔离、地址更新、重名重排、推荐排序和首页焦点坐标纯逻辑单测。`testDebugUnitTest`、`lintDebug`、Debug 与 Release 构建通过；720p/1080p 模拟器验证实际播放、遥控器切台、重启保留、A/B 节目源隔离、搜索推荐、设置清除和返回焦点。搜索页返回时发现并修复了卡片解绑调用已销毁 Activity 的崩溃。

验收：重启应用后仍能找到最近频道；换源、频道下线和重名频道不会打开错误地址；清除记录后推荐区同步更新。

### P1-3：播放中快速选台

- 在播放页提供可由常见遥控器按键打开的频道目录，含当前分组、收藏和最近观看；明确与现有上下键顺序切台、确认键信息层的按键关系。
- 打开目录时当前播放不停止，取消返回原频道；选中后切台并关闭目录。

验收：无需退出播放即可直达其他分组频道；打开、切换、返回过程焦点和音视频生命周期正确。

### P2：性能、无障碍与发布回归

- 完成旧计划剩余的预览画面淡入、滚动期任务节制、文字对比度与 TalkBack 检查。
- 建立 720p/1080p 模拟器遥控器路径回归；真机仅覆盖模拟器难以代表的输入法、解码与性能场景。
- 对节目源刷新、缓存回退、设置返回、收藏和静态预览建立小范围回归清单。
